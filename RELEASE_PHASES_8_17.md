# PhishGuard Phase 8–17 Release Notes

Date: 2026-10-12

## Implemented

1. **Character-level model path:** retains URL char, word, host-char, LinearSVC char, and `char_wb` learners in the seven-component ensemble.
2. **Unicode/Punycode diagnostics:** `app/unicode_url.py` reports IDNA round-trip, mixed-script, confusable, bidi and invisible-format signals. These do not hardcode a verdict.
3. **Complementary learners:** seven component models combine through the trained meta-model.
4. **Calibration:** ensemble Platt/logistic calibration remains; trainer now adds a separately calibrated XGBoost fast stage using OOF probabilities.
5. **Precision/recall operating point:** threshold report and calibration-fold threshold selection are persisted; outer holdout is evaluation-only.
6. **Risk zones:** URL decisions are benign/suspicious/phishing; suspicious has `binary_verdict=unknown`. Unknown model/email paths do not fake a benign decision.
7. **Fast path:** the fast stage is enabled only if calibration constraints and outer unseen-domain non-regression pass. The existing promoted model has no dedicated fast calibration and is safely routed through the full ensemble.
8. **Local intel:** SHA-256 digest index for canonical exact URL matches; URL path and query remain scoped. Refresher and serving default directories are aligned.
9. **Deep analysis:** optional bounded DNS/TLS is performed only for suspicious single-URL requests when `DEEP_ANALYSIS_ON_UNCERTAIN=true`. Socket work runs via `asyncio.to_thread`; missing/failed evidence never marks a URL benign. Remote enrichments remain opt-in and admin-gated.
10. **Cache:** bounded L1 plus optional Redis L2, per-entry TTL, model-version-keyed scores, shorter lifetime for near-threshold scores, caching for configured providers and DNS/TLS origin evidence.

## Actual candidate gate outcome

A candidate was trained using traceable supplied labeled data after excluding reserved exact URLs, the archived OpenPhish holdout domains, and the frozen regression URLs. The candidate's outer unseen-domain result was:

- Accuracy: 98.39%
- Precision: 99.24%
- Recall: 97.04%
- F1: 98.13%
- Domain overlap: 0

The fast cascade achieved 96.30% recall on the outer holdout versus 97.04% for the full calibrated ensemble, a 0.74 percentage-point recall drop. The configured maximum is 0.50 percentage points, so the fast path was disabled for this candidate.

Frozen regression for the candidate was 98.12% accuracy, 100% precision, 96.23% recall. It did not meet the current frozen regression recall gate (98%), and was not promoted. The production pointer remains `v20261001_104517`.

## Current production limitation

The currently promoted model has no separate fast-stage calibrator, so production will not short-circuit model decisions using raw XGBoost probabilities. The full calibrated ensemble remains active. To enable the fast path, a future candidate must clear the same thresholds and frozen gates; speed is not allowed to trade away unbounded recall.

## Real-world data freshness

The captured OpenPhish URLs are dated 2026-10-05 and are now archived historical data, not a current live-feed claim. Current sources are retrieved by `scripts/refresh_feeds.py` only when run in an Internet-enabled environment. Feed refresh outputs contain retrieval timestamp, source URL, SHA-256, count, and a `listed_urls_visited=false` marker. The refresher does not visit any URL contained inside the feed.

## Final regression notes (2026-10-12)

Additional regression tests cover chronological split boundaries, duplicate URL removal across a temporal boundary, invalid timestamps, cached provider enrichment, cache-disable behavior, feed-empty-response protection, and concurrency slots after timed-out DNS/TLS work. The active model's fast path remains disabled: speed shortcuts are not enabled from uncalibrated scores.

The current October 5 OpenPhish artifact is historical. The build runtime could not verify a fresh feed download; `scripts/refresh_feeds.py --once --feed-dir data/feeds/live` must be run from an Internet-enabled environment. CVE scanning and cluster-scale tests are likewise external release gates, not passing claims.
